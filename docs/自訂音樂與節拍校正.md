# 自訂音樂、BPM 與節拍校正

選關畫面按 **M** 或「音樂設定」，選擇至少 8 秒、32 MB 以內的 WAV、MP3 或 OGG Vorbis。音訊在裝置內分析，不會傳到伺服器。

1. 選檔後會自動估計 BPM 與歌曲第一個拍點。最多分析前 90 秒，畫面顯示進度。
2. 按「試聽」，比較鼓點、拍點提示音與圓圈。BPM 可手動修改；若辨識成半拍或雙拍，可按「÷ 2／× 2」。
3. 跟著音樂鼓點按空白鍵，會逐步校正拍點位置。至少敲四次後，可按「敲擊推估 BPM」採用敲擊速度。
4. 「第 1 拍位置」以毫秒表示，包含歌曲前奏；可拖曳試聽進度、按「此刻設為第 1 拍」，再用 ±10 ms 微調。這會以該處作為遊戲節奏的起點。
5. 按「套用並返回」才保存並套用。取消保留先前的歌曲。每首歌以內容指紋保存 BPM／第一拍設定；再次選入相同檔案會讀回校正。
6. 藍牙、耳機等裝置延遲仍用選關畫面的 **O** 校正；它與歌曲本身的第一拍偏移分開保存。

## 速度關係

關卡的距離與跳躍物理仍以 120 BPM 設計，透過整體時間倍率保持可通關比例：

- 世界倍率 = 歌曲 BPM ÷ 120 × 變速線倍率。
- 音樂播放倍率 = 變速線倍率。
- 實際聽到的 BPM = 歌曲 BPM × 變速線倍率。

例如 150 BPM 歌曲，正常段落音樂原速 1×、世界 1.25×；通過 1.2× 變速線後，音樂變成 180 BPM、世界 1.5×。選關及校正介面維持正常速度。

自訂歌曲結束前，會在完整八拍的邊界循環回第 1 拍（短曲使用四拍），節拍時鐘持續累加。循環不保證音樂編曲或音色接縫完全自然。

## 偵測限制與儲存

這是固定 BPM 推估，不會自動產生關卡，也不會追蹤歌曲中途的自由變速。弱鼓點、切分、三拍、長前奏或自由速度歌曲可能誤判，請試聽、手動調整或換曲。自動第一拍估計的是可用拍點，無法保證辨識到編曲上的強拍或小節頭。

使用 Godot 原生音訊解碼，不依賴外部服務。Web 使用 JavaScriptBridge 接瀏覽器選檔。`scripts/web/music_picker.js` **不是** Godot resource，匯出預設不會進包；`export_presets.cfg` 的 `include_filter` 須含 `scripts/web/*.js`。另有 `MusicPickerEmbed` 內嵌備援；若只改了 `.js`，請跑 `python3 tools/embed_music_picker.py` 同步。瀏覽器需由玩家操作啟動播放。

itch.io 會把遊戲嵌在 iframe 裡，直接從 Godot 觸發的隱藏 `input.click()` 常被瀏覽器擋掉。目前的 `music_picker.js` 會改開一層 **HTML 選檔遮罩**（按鈕點選或拖放檔案），讓選檔發生在真實的使用者手勢裡，嵌入模式也能用。若仍失敗，請改用「在新分頁開啟」或桌面版。

`user://custom_music.audio` 保存目前歌曲，`user://custom_music.cfg` 保存歌曲設定與內容指紋。桌面會保存到遊戲使用者資料夾；網頁依瀏覽器對該網站的本機儲存政策保留，清除網站資料或無痕模式可能失去保存內容。請上傳完整 Web 匯出檔，而非只上傳 HTML。

## 驗證方式

```sh
python3 tools/generate_bpm_fixtures.py
Godot --headless --path . --fixed-fps 120 --script res://tools/check_custom_music.gd
Godot --headless --path . --fixed-fps 120 --script res://tools/check_climbing_levels.gd
Godot --headless --path . --export-release Web build/web/index.html
python3 -m http.server 8765 --directory build/web
# 另一個終端機，需安裝 Playwright 並設定 Chrome 路徑（預設 macOS Chrome）
PLAYWRIGHT_MODULE=/path/to/playwright node tools/check_music_web.cjs
```

測試音訊由程式產生於被忽略的 `build/music_tests/`；涵蓋多種 BPM、非整數 BPM、壓縮格式、前奏、靜音、實際第五關變速與歌曲校正保存。網頁測試使用啟用 sandbox 的 iframe，驗證真正的選檔、試聽、對拍、套用、重新載入與恢復內建音樂。
